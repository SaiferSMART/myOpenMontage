## A. ИНВЕНТАРЬ

### A.0 Как устроен проект (одна страница)

Система **instruction-driven**: интеллект — у агента (Cursor/Claude и т.п.), Python — инструменты + чекпоинты, YAML в `pipeline_defs/` — манифесты стадий, markdown в `skills/` — «как делать стадию», `.agents/skills/` — знания про внешние API/рантаймы. Продкшн **не** запускается ad-hoc скриптами: агент обязан выбрать пайплайн → preflight реестра → стадии с review/checkpoint.

Рендер-движки композиции (локально): **FFmpeg** (простые склейки), **Remotion** (React, `remotion-composer/`), **HyperFrames** (HTML/CSS/GSAP через `npx`, нужен Node ≥ 22). Генерация видео нейросетями — почти всё через платные API; локальные модели помечены `LOCAL_GPU` и без NVIDIA почти бесполезны.

В `pipeline_defs/` лежит **13 YAML**: **12 продакшн-пайплайнов** + `framework-smoke` (служебный smoke для контрактов фреймворка, не для контента).

### A.2 Стили-плейбуки (`styles/*.yaml`) — отдельно

Это не пайплайны, а **визуальные playbook’и** (палитра, шрифты, темп, mood, «best for»), валидируются схемой playbook. Загружаются лоадером плейбуков. Имеет смысл держать как каталог «настроек вида» при proposal, **не копируя YAML в свой продукт**.

| Playbook | Категория / mood | Зачем владельцу |
|----------|------------------|-----------------|
| **clean-professional** | motion-graphics, спокойный «корпоратив» | YouTube-объяснялки, спокойные промо |
| **premium-minimalist** | minimalist, редакционный, с anti-patterns | Дорогие launch/экспертные ролики |
| **flat-motion-graphics** | тёмный, энергичный, соцсети | Instagram/Shorts, быстрые промо |
| **minimalist-diagram** | whiteboard / технический | Редко — только tech-deepdive |
| **anime-ghibli** | иллюстративный anime | Скорее нет для эфирного бренда |

В INDEX также фигурирует связка playbook ↔ пайплайн (explainer любит clean/flat; animation — flat/anime; talking-head — clean).

### A.4 Skills (`skills/INDEX.md`) — что читать владельцу

Трёхслойная модель: реестр tools → `skills/` (как OpenMontage этим пользуется) → `.agents/skills/` (как устроены Remotion/HF/ElevenLabs/…).

**Для профиля читать в первую очередь (Layer 2):**

- Пайплайн-директора: `clip-factory/*`, `talking-head/*`, `hybrid/*`, `explainer/*` (для промо), `localization-dub/*`
- Creative: `short-form.md`, `typography.md`, `storytelling.md`, `sound-design.md`, `video-editing.md`, `subtitle-sync` (core)
- Meta: `checkpoint-protocol`, `reviewer`, `onboarding`, `voice-performance-director`, `animation-runtime-selector`

**Layer 3, релевантные ключи:** `elevenlabs`, `speech-to-text` / `azure-speech-to-text`, `ffmpeg`, `remotion*`, `hyperframes-*` (если пойдёте в кинетику), `create-video` / `heygen` / `avatar-video` — только если появится HeyGen.

Не тратить время сначала: Three.js-набор, ManimGL, LTX/ComfyUI, faceswap/локальный avatar.

## B. ИДЕИ ДЛЯ ЗАИМСТВОВАНИЯ (подходы, не код)

Ниже — пересказ подходов своими словами. Не копировать файлы skills в продукт; воспроизводить **метод** в своих гайдах/чеклистах под AGPL-ограничениями.

### B.1 Locked narration vs storyboard (`hyperframes-core` → script-format)

Суть: разделить «черновой voiceover в раскадровке» и **зафиксированный SCRIPT** — финальные реплики + голос + настройки + per-line delivery. Время в скрипте — ориентир; авторитетные тайминги появляются после TTS с word timestamps. В TTS уходит только блок произносимого текста, не метаданные.  
Силён тем, что голос не «плывёт» от итераций картинки.  
**Применимо:** промо с ElevenLabs — один locked script на ролик, правки delivery отдельно от раскадровки.

### B.2 Написание дикторского текста (`hyperframes-creative` → narration)

Суть: целевой темп ~2.5 слова/сек (скрипт короче видео), разговорный тон, контракции, вариация длины фраз. Числа и аббревиатуры писать **как произносить**, а на экране можно оставить точную цифру. Структура Hook → Story → Proof → CTA; открывающая фраза обязана создать напряжение за 3 секунды.  
Силён предсказуемой длительностью и естественным TTS.  
**Применимо:** все промо и анонсы эфиров на русском (адаптировать нормы произношения: «API» → «а-пэ-и» / «эй-пи-ай» — выбрать и зафиксировать в глоссарии).

### B.3 House style без брендбука (`house-style`)

Суть: до вёрстки объявить палитру (bg/fg/accent), шрифты, свет/тёмную тему под жанр; сознательно избегать «AI-дефолтов» (gradient text, cyan/purple неон, одинаковые карточки). Фон сцены — не пустой: 2–5 декоративных слоёв с **одной** общей ambient-анимацией. Палитры сгруппированы по mood (bold, warm editorial, dark premium…).  
Силён как анти-шаблон и скорость старта.  
**Применимо:** единый визуальный язык YouTube/IG промо; сопоставить с playbook’ами `styles/` (flat для Reels, clean/premium для длинного YouTube).

### B.4 Авторство субтитров (`hyperframes-media` → captions/authoring)

Суть: стиль captions выводить из тона транскрипта (4 оси: feel / palette / font / animation). Группировка слов по энергии (2–3 / 3–5 / 4–6). Позиции: landscape низ; portrait — выше UI платформы. Per-word акцент на бренд, CAPS, числа, эмоции, CTA. Жёсткий exit каждой группы + self-lint «группа не должна остаться видимой». Для не-английского — **не** брать `.en` Whisper-модели (они переводят, а не транскрибируют).  
Силён как продакшн-чеклист, особенно для русского.  
**Применимо:** обязательно для clip-factory / talking-head на русском (`--language ru`, модель без `.en`).

### B.5 Именованные текстовые эффекты (`animate-text` adapter)

Суть: не изобретать easing каждый раз — в раскадровке указывать **ID эффекта** из каталога (typewriter, per-word-crossfade, mask-reveal…). Рецепты живут отдельно (внешний skill); при отсутствии — fallback по смыслу имени.  
Силён единообразием серии роликов.  
**Применимо:** титры промо / kinetic lower-thirds; завести свой короткий словарь 5–7 эффектов под бренд (идея каталога, не копирование JSON).

### B.6 Blueprint typewriter-reveal

Суть: готовый «сценарий кадра» 3.6–7 с: caret печатает → правка/backspace или swap → collapse → spring-pop бренда **или** persistent logo + typing CTA. Роли: Hook vs Brand_Outro.  
Силён как шаблон хука/аутро без генеративного видео.  
**Применимо:** intros анонсов эфиров и end-cards YouTube/IG — чисто Remotion/HF, без GPU.

### B.7 Библиотека mood-стилей (`create-video` → visual-styles)

Суть: ~20 именованных стилей с mood + дизайнер-референс + палитра + типографика + motion; выбор по чувству («что зритель должен почувствовать»), в промпт класть STYLE-блок, не примеры B-roll.  
Силён как язык брифа для агента/дизайнера.  
**Применимо:** сузить до 3–4 «своих» стилей под каналы; связать с `styles/*.yaml`.

### B.8 Скрипты для avatar-TTS (heygen / avatar-video → scripts)

Суть: ~150 wpm; короткие предложения 10–20 слов; пунктуация = паузы; явные break-теги с пробелами вокруг; избегать скороговорок. (Файлы heygen и avatar-video по scripts/captions/voices/overlays по сути дублируют один и тот же гайд.)  
Силён стабильным lip/TTS.  
**Применимо:** напрямую к ElevenLabs-скриптам владельца (даже без HeyGen).

### B.9 Голоса и локали (voices)

Суть: голос выбирать списком API (язык/пол/emotion/pause support), фиксировать voice_id в locked script; скорость/pitch — осознанно.  
Силён воспроизводимостью серии.  
**Применимо:** один «голос канала» ElevenLabs + русский locale; не менять mid-series без записи в decision log (в OpenMontage это отдельная дисциплина).

### B.10 Captions у avatar-сервисов vs свои

Суть: у HeyGen captions — флаг/стиль/язык «из коробки», но контроль слабее, чем у своего Remotion word-highlight пайплайна.  
Силён скоростью; слаб кастомом.  
**Применимо:** владельцу лучше **свой** subtitle pipeline (уже есть в talking-head/clip-factory), а не полагаться на облачные captions.

### B.11 Text overlays (text-overlays)

Суть: координатная система от top-left, типовые позиции (lower third, top center), длительность start/end, контраст и safe zones.  
Силён как памятка вёрстки титров.  
**Применимо:** нижние трети на эфирных нарезках; сверять с safe zones short-form (низ экрана занят UI IG/TikTok/Shorts).

### B.12 Аудио → данные для motion (`extract-audio-data.py`)

Суть: идея конвейера — ffmpeg декодирует в PCM → по кадрам RMS + лог-полосы FFT → JSON для барграфов/пульсации в композиции. Окно FFT шире кадра, чтобы басы не схлопывались.  
Силён дешёвой «музыкальной картинкой» без gen-видео.  
**Применимо:** audiogram/podcast-клипы и интро под трек; реализовать **свой** скрипт с нуля (AGPL: не копировать), сохранив идею «пререндер audio features → анимация».

### B.13 Дополнительно найденное (сценарий / титры)

**Explainer-дуга (storytelling skill):** Hook → gap → 3 концепта с «palette cleanser» → proof → CTA; пауза после insight. Масштабировать до 15–60 с для Shorts.  
**Типографика видео:** лимиты символов/строк, title/action safe, контраст WCAG, 1–2 семьи шрифтов, размер субтитров ≥ ~3–5% высоты кадра.  
**Short-form:** универсальная safe zone ~900×1400 в 1080×1920; hook в 1–2 с; captions обязательны (много смотрят без звука); смена картинки каждые 1–3 с.  
**Language Rule транскрипции:** для русского всегда multilingual Whisper + `language=ru`; иначе получите английский «перевод» субтитров — прямой риск для профиля.  
**Decision log / runtime choice:** фиксировать провайдера TTS и Remotion vs HF до дорогих шагов; не молча подменять — полезно перенести как процессную дисциплину в свой пайплайн монтажа.

## C. ЛОКАЛЬНЫЙ ЗАПУСК (только анализ, ничего не запускалось)

### C.1 Что обещает репо «из коробки»

- `make setup` / PowerShell-эквивалент: venv Python **3.10+**, `requirements.txt`, `npm install` в `remotion-composer`, опционально `piper-tts`, прогрев `npx hyperframes`, копирование `.env.example` → `.env`.
- `make demo` / `render_demo.py`: **zero-key** рендер 3 Remotion-фикстур (`world-in-numbers`, `code-to-screen`, `focusflow-pitch`) → `projects/demos/renders/*.mp4`. Нужны Node/npm/npx + зависимости Remotion; **API-ключи не нужны**.
- `render-demo.sh` — тонкая обёртка под unix-shell; на Windows логичнее `python render_demo.py`.
- `requirements-gpu.txt`: только torch-стек; отдельно diffusers/transformers в `make install-gpu`.
- HyperFrames: отдельный doctor; **Node major ≥ 22** (Remotion-демо может жить на Node 18+, HF — нет).

### C.2 Чек-лист установки на Windows 11 (без GPU)

1. **Python 3.10+** (в репо `.python-version` = 3.10). Установить с python.org, галка PATH.
2. **FFmpeg** в PATH (`ffmpeg -version`, `ffprobe -version`) — без него trim/mix/compose/STT-препроцессинг разваливаются.
3. **Node.js:** минимум 18 для Remotion-демо; **22+**, если планируется HyperFrames.
4. **Git** (уже для клона форка).
5. Создать venv и поставить core deps (как в README Windows PowerShell-блоке): venv → `pip install -r requirements.txt` → `cd remotion-composer; npm install` (если `ERR_INVALID_ARG_TYPE` — `npx --yes npm install`) → опционально `piper-tts` → скопировать `.env`.
6. В `.env` для профиля минимум: **`ELEVENLABS_API_KEY`**. Желательно: сток (`PEXELS`/`PIXABAY`), при желании Azure STT для русского, `OPENAI`/`FAL`/`GOOGLE` — только если нужны картинки/видеоген. **Не ставить** ожидание на `VIDEO_GEN_LOCAL_*` без GPU.
7. Дополнительно для эфиров: `pip install faster-whisper` (и при необходимости whisperx); модель `small`/`medium` + `language=ru`.
8. Проверка без ключей: `python render_demo.py --list` затем один демо-ролик.
9. Проверка реестра: `python -c "… registry.provider_menu() …"` / `make preflight` (если есть make; на Windows часто через Git Bash или ручной вызов python).
10. HyperFrames (опционально): Node 22+, `npx hyperframes --version`, doctor через python-tool/`make hyperframes-doctor`.

### C.4 Вердикт

**Поедет частично.**

- **Поедет уверенно:** установка Python+ffmpeg+Node, Remotion zero-key demos, локальный монтаж эфиров (trim/stitch), CPU-Whisper с `ru`, выжигание субтитров через Remotion, промо с **ElevenLabs**, пайплайны **clip-factory / talking-head / hybrid** без GPU-enhancement.  
- **Поедет при доп. ключах:** сток B-roll, image gen для explainer, облачный STT, музыка Suno/ElevenLabs music.  
- **Не поедет на этой машине:** локальные video/avatar/upscale/ComfyUI/`requirements-gpu` сценарии; комфортный CLIP-documentary; HyperFrames — только после Node 22.  
- **Процессный нюанс:** сам репозиторий — агентская ОС под AGPL; «просто библиотека функций» без соблюдения лицензии в закрытый продукт — нельзя. Имеет смысл либо работать **внутри** форка как AGPL-инструмента, либо заимствовать только подходы (раздел B) в своей отдельной реализации.
